# Правила для агента

Редизайн маркетингового лендинга Pricing.su.

## Документация

- `PRODUCT.md` — продукт, ограничения контента и функциональности, принципы, a11y.
- `DESIGN.md` — токены, компоненты, poster-слой (≥1440px).
- `styleguide.html` — визуальные примеры (1440px).
- `design/client-feedback.md` — замечания клиента по секциям.
- `index.html`, `index2.html` — рабочий код; `original/` — исходник, не изменять.

## Файлы

- Правки в `index.html` и `index2.html` — синхронно в оба, пока пользователь не разведёт версии. Не копируй один файл поверх другого: применяй согласованные изменения к каждому отдельно.

## Как работать

- Перед редизайном прочитай `PRODUCT.md` и `DESIGN.md`.
- Одна секция за раз; минимальный diff; не рефактори лишнее.
- Соблюдай ограничения из `PRODUCT.md` (тексты, функциональность, факты).
- После изменений проверяй результат в браузере.
- Git commit — только по прямому указанию.
- В ответах пользователю не используй таблицы; пиши списками и обычным текстом.

## Контекст и проверки

- Не исследуй весь репозиторий без необходимости; не перечитывай неизменённые файлы.
- Если задача укладывается в 1–3 файла — не трогай остальное.
- Предпочитай точечный поиск и короткий вывод команд.
- Полный test suite — только по запросу.
- Ответы и статус — кратко.

## Локальные скиллы

Перед утверждением, что скилл недоступен, рекурсивно найди все `SKILL.md` в каталогах `skills` проекта (включая `.agents/skills/`).

- Не применяй скиллы без согласия пользователя. Вызов по имени или `$имя-скилла` — согласие только на этот скилл в текущей задаче.
- Если скилл полезен — назови, кратко объясни и спроси разрешение; до ответа делай только независимую работу.
